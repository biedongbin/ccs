## 一、项目概况

| 维度 | 现状 |
|---|---|
| 形态 | Python 单文件 `ccs`（1740 行，纯标准库）+ Node/ink 移植 `ts/src`（8 模块 ≈1600 行），功能等价双胞胎 |

## 二、设计优点（保持勿动）

1. **解析层鲁棒性**：64KB 头尾采样 + 缺侧全扫兜底 + `INTERNAL_PREFIXES` 样板过滤 + sidecar 折叠 + 四级标题链——对上游 jsonl schema 漂移防御充分，"解析永不抛错"贯彻到位。
2. **数据安全纪律**：永不 `rm`、全程 `move` 原子移动、唯一写例外（rename 追加 `custom-title`）与官方 `/rename` 同构。
3. **双版一致性机制**：i18n 单源导出、EAW 宽度表生成、parity 基准锁定——工程纪律高于同类个人项目。
4. **resume 语义**：编码目录反解启动目录 + `$SHELL -ic` 保函数/alias + 绝不静默降级当前目录，边界处理完备。

## 三、缺陷清单

### A. 功能缺陷（已实证）

**A1 · S 键守卫失效** — `ccs:1658`
```python
elif k == "S" and st.current() is not None or k == "S":
```
`and` 优先于 `or`，条件恒等于 `k == "S"`——空列表仍弹语义输入框，向空清单发起 `claude -p`。
实证：`cond("S", has_cur=False) == True`。
修：`(k == "S" and st.current() is not None)`。

**A2 · 语义范围注记方向反转 + 双版背离** — `ccs:537`
```python
window = "" if len(cands) < len(sessions[:100]) or not sessions else "（范围：最近 15 天）"
```
实证（混合新旧会话 = 过滤生效）：prompt **不含**"范围：最近 15 天"；全集都在窗内（未过滤）反而**含**——三元反了。
TS 版 `ts/src/summary.ts:29` 语义正确，即两版行为相反，违反"逐语义移植"纪律；
`ts/test/tui.test.cjs:194` 注释自称"Python 同语义"，与事实不符。
修：Python 三元反转对齐 TS。

### B. 一致性缺口

| # | 问题 | 位置/说明 |
|---|---|---|
| B1 | parity 盲区 | 基准只覆盖 parse/launch_dir/scan/width/store；semantic/summary prompt、resume argv、config 均不在对拍内。A2 即从此缝隙漏出（`tools/dump_py.py` 未导出该组） |
| B2 | Node CLI 面缺口 | `ts/src/cli.ts` 不认 `-r/--refresh`（静默无效）、无 `--help`；README 键表未注明 Node 差异 |
| B3 | Node 无缓存层 | `ts/src/scan.ts:scanAll` 每次全量重解析——`a/u/d`、每次后台任务完成都 rescan 全部文件；含全扫兜底触发条件的会话（无有效指令文件）每次**全文件读**。而 `docs/architecture.md:43` 声称"缓存互通"，属文档过度承诺。Python 侧 cache.json 键控完备，Node 侧零实现 |
| B4 | TS picker 无视口滚动 | Python 有 `poff` 滚动窗，`ts/src/app.tsx` picker 整页 `items.map` 不裁剪——项目数超过终端高度即溢出破版 |

### C. 性能

| # | 问题 | 说明 |
|---|---|---|
| C1 | 每帧重读 summaries.json | Python 主循环 `ccs:1501,1558` 每次按键/每 500ms 轮询都 `load_summaries()`（全量 JSON.parse），`st.sums` 内存态已在却不用；TS `detailLines()` 同病（`sumsForFilter` 依赖 `msg` 频繁重算）。总结积累到百条（≈2MB）时每键可感卡顿 |
| C2 | cache.json 无界增长 | 键=`path+mtime_ns`，归档/删除/移动后旧键永留；summaries.json 对已 trash 会话的条目同样残留 |

### D. 安全加固

| # | 问题 | 说明 |
|---|---|---|
| D1 | sid 裸拼 shell 串 | `ccs:642` / `ts/src/resume.ts:42` 将 `sessionId` 未经引号插入 `$SHELL -ic "... --resume {sid}"`。sessionId 取自 jsonl 内容——导入外来会话文件即构成命令注入面。修：`shlex.quote(m.sid)`（含 `{sid}` 自定义模板场景同样兼容） |
| D2 | 语义搜索无工具限制 | summary 调用带 `--allowedTools Read`，语义调用（`build_semantic_argv`）无任何限制；且会话 title/cmds（攻击者可控文本）直接拼入 prompt——prompt injection 面。修：附加最小 `--allowedTools` |
| D3 | Python resume 失败路径 | `ccs:998` 先 `endwin()` 再 `execvp`，spawn 失败时 curses 已拆、循环回到坏终端（TS 版干净 `exit 1`，行为不一致） |

### E. 小项

- README（en）测试数 "47 checks" 漂移，实际 53；
- `ts/src/app.tsx:402` 死条件：`(sel ? cut(...) : cut(...))` 两分支相同；
- `config.json.tmp` 固定临时名（双开竞态）vs summaries 的 pid 后缀——同库两种纪律；
- `_cut`（`ord>0x2E80`）与 `_dw`（EAW A=2）口径不一：歧义宽字符（é/西里尔）垫列错位——parity 锁定的既定取舍，记录即可；
- `run_check` 输出硬编码中文（两版同），i18n 域外。
